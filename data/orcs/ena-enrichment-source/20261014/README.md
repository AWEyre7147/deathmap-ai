# ORCS ENA metadata enrichment

Retrieval: 2026-10-14. Owner accepted the broad-project boundary on 2026-10-16.
This package preserves native ENA responses, request receipts, source input
snapshots, original execution code and the resulting canonical metadata.

All 418 ORCS publications were processed. The run resolved 533 candidate
study/project records linked through discovery observations to 191 publications.
These are candidate publication associations, not adjudicated qualifying screens
or 533 necessarily independent scientific datasets.

## Scope

Exact PubMed cross-references, complete publication-title phrases and saved
GEO/PubMed BioProject/SRA links supplied candidate identifiers. Native XML resolves
study aliases. GEO lookup is a fallback where saved study links do not resolve.
Duplicate EBI PMID queries, DOI/PMCID searches and shorter-title searches are not
active discovery routes. Historical pilot evidence remains unchanged.

Complete-title search added 20 candidate publication/project pairs beyond the
other routes, including three publications without saved PMIDs; it is retained.
Among all 561 candidate pairs, native ENA citation metadata matches the search
PMID for 281, differs for 205, lacks a native PMID for 72, and cannot be compared
for three publications without a search PMID. These distinctions remain in
canonical evidence; the owner template shows Search PMID and ENA PMID separately.

No publication bodies, supplementary documents or experimental data files were
downloaded. File locations, sizes and checksums are descriptive metadata only.

## Broad-project boundary

The following project records and native hierarchy are retained without expanding
their collection-wide children:

- PRJEB40771: INSDC COVID-19 Infected Human Sequencing Data.
- PRJEB40772: INSDC Non-Human Coronavirus Host Sequencing Data.
- PRJNA63443: Production ENCODE epigenomic data.

Their reports exceeded the 32 MiB per-response boundary. Following the owner's
acceptance of AH4, their broad publication links do not propagate to all children.
Child counts remain blank, not zero. Independently identified constituent studies
retain their own retrieved metadata. The other 530 run reports are complete.

## Contents and verification

- `manifest.json`: original inputs, hashes, strategy and operational limits.
- `requests.json` and `raw/`: exact URLs, UTC dates, sizes, hashes and responses.
  Semantic error responses remain preserved and marked incomplete where applicable.
- `scope-decision.json`: the accepted project-only exceptions and checkpoint hash.
- `size-checkpoint.json`: the original response-size checkpoint, before recovery.
- `title-recovery.json` and `run-report-recovery.json`: bounded recovery of three
  title queries and three server-error reports; no second full pass was run.
- `summary.json`: candidate, route and selected-sheet counts.
- `executed-code/`: original retrieval code; later recovery/export code is recorded
  alongside it without replacing the original execution snapshot.
- `source-verification.json`: response-hash checks and Excel cell-size preflight.
- Workbook receipt and verification files are generated by the final export.

Selected metadata contains 10,592 sample records, 14,322 native ENA experiment
records, 16,253 distinct sequencing runs and 25,227 file-listing rows. Differing
native child-record values remain separate rather than forcing a single value.
Parent/child reporting memberships are retained without adding repeated runs to
the distinct total.

The registered seven-sheet template is `data/templates/ENA-Enrichment.xlsx`.
It remains unchanged. Canonical JSON retains evidence omitted from the selected
workbook fields, including unresolved citation links and source locators.

The final workbook is `data/orcs/ENA-Enrichment.xlsx`; its compact canonical JSON
is `data/orcs/ena-enrichment.json`. The original intermediate database bytes are
retained in `database.json.gz`, with the verified uncompressed hash recorded in
`database-preservation.json`. No raw response bytes were altered.

The spreadsheet-engine save reached its 4 GiB heap limit. The existing Python XML
writer saved the same projected data, preserving the template envelope; all
607,554 exported cells and seven template-header/settings blocks were verified.
Twelve focused checks passed. Small excerpts read from the saved workbook were
rendered and inspected. Native Excel application opening was not tested.
One-off recovery, render and release helpers are retained under executed-code;
`cleanup-receipt.json` records their unchanged bytes and former paths. Active ENA
retrieval and export live in `deathmap_ai.ena_collection` and `ena_workbook`.
Sample/experiment fields come from run reports; separate child XML was not fetched.
